# 《影迹》竞速信息与反馈改进方案 V1

日期：2026-09-05

状态：第一版已实施，自动化测试、界面渲染和 Windows 验证包已完成；陌生玩家验收待进行。依据当前源码及《描述影迹现状》分享会话整理。

用户确认的视觉方向：深灰底、蓝白文字与普通强调，少量橙色用于主要按钮和关键变化。降低装饰线和高饱和发光的存在感。这个方向应用于界面；赛道的预测、反制和安全标记仍沿用现有玩法语义。

## 1. 这一版解决什么

让玩家在高速中把注意力放在路线、障碍和回声上。把需要理解的规则放在开跑前，把需要解释的观察放到结束后；赛中只显示维持比赛所必需的信息，以及少量及时反馈。

第一版的完成标准：玩家不靠持续读提示也能跑完挑战，知道自己领先还是落后、还能承受多少碰撞，并且不会把一次操作失误误读成“AI证明我没有改变”。

本版以现有竞速流程为基础：先调整信息分配、提示生命周期和反馈语义。两局约90秒、自选立约、不同诱因探测、回声提前押线等设计，作为后续可单独验证的改动，不绑进本次HUD改进。

## 2. 玩家会看到什么

| 阶段 | 第一版呈现 | 玩家此时需要做什么 |
| --- | --- | --- |
| 开跑前 | 在现有首页卡片中展示一句近期观察，以及“领先回声到终点”的目标。证据不足时显示“还需要观察”。使用现有开始按钮。 | 看懂目标，准备好再开始。 |
| 跑动中 | 左上角固定显示领先/落后、终点进度、伤势或剩余容错。路线、障碍、金币和回声动作承担主要信息。 | 看赛道，作出操作。 |
| 关键事件后 | 在不遮挡前方赛道的位置出现一条短反馈，随后淡出。 | 快速确认刚才发生了什么。 |
| 结束后 | 在现有结算页分开呈现比赛结果、关键选择、执行结果和下一局将使用的记录。 | 对照自己的行为，理解下一局。 |

首页观察文案只描述现有证据。例如“近期选路：偏右”，不把车道记录升级为“你抵抗不了高价值奖励”或人格判断。

### 常驻信息

- 左上角组成一块紧凑区域：领先/落后最明显，进度和伤势次之。使用文字、数字、图标共同表达，不能只靠颜色。
- 伤势直接影响碰撞容错，保留“伤势 0/2”、受伤后的“恢复中”和“再受伤即出局”。护盾或恢复期可以吸收碰撞，因此用“再受伤”描述出局条件。分数和金币维持为次要信息。
- 当前没有玩家自选立约入口。本版不增加一个空有标题的“本局立约”常驻栏。
- 常驻的长预测句和整段颜色教学退出跑动主视区。首次教学移到开始前，局内不反复解释规则。

### 临时提示

- 复用现有提示文字与底板，增加独立透明度控制。
- 第一组试用参数：淡入0.15秒、停留1.7秒、淡出0.35秒，共2.2秒。参数可调，最终以实机可读性为准。
- 同时最多一条；按事件触发，不因每帧刷新而重新计时。
- 同一个探测门连续产生的结果与“改猜”反馈合成一句。重要提示覆盖普通提示，过期消息直接丢弃，不排队延迟播报。
- 优先保留关键规则变化、伤势变化、有效探测结果；普通金币获取和无变化状态不追加文字提示。
- 跑动中不弹长句、不要求确认、不暂停比赛。动画关闭或减少动态效果时，提示仍可清楚显示，不依赖闪烁或位移。

### 路线信号

- 需要玩家据此操作的地面标记，保留到这次选择结束，不能为了淡出而提前消失。
- 本版保留现有预测/反制/安全路线的游戏规则。地面分别增加矩形、三角和双横线，并保留既有颜色语义；开跑前用一行说明对应关系。形状补充颜色信息，是否能在高速中认出仍需试玩。
- “把整个决策区做成中性探测信号”与当前明确的反制路线规则存在设计差异，后续与新的探测场景一起试验。本版不只换一套颜色就宣称已解决这一问题。

## 3. 先把反馈说准确

当前已经分开记录路线选择与执行结果，可以复用。需要补足的是失败原因和表述边界。

| 已有证据 | 建议表达方向 | 避免表达 |
| --- | --- | --- |
| 提交了反制路线，并成功通过 | “反制通过”，结合现有领先变化提示。 | 由一次成功推断人格或永久习惯变化。 |
| 提交了反制路线，但未完成通过 | “尝试反制 · 通过未完成”。详情留到结算。 | “没骗过它”“它猜中了”。 |
| 选择符合预测，并成功通过 | “本次选择符合预测”。 | “你果然还是这样”。 |
| 未确认通过 | “通过结果未确认”，在结算说明证据缺口，竞速计分沿用现行规则。 | “本次不计”，让玩家误以为竞速计分也被取消。 |
| 后续预测已调整 | “后续预测已调整”。 | 当前代码仅改猜时，声称已换了一种探测方法。 |

实现时明确三件事：

1. 当前换道途中可以反向。CurrentLane表示输入目标，角色实际横向位置另存；保留移动手感，并在现有门记录中补充目标、实际位置和是否仍在换道，避免把目标车道当成身体已到达的证据。
2. 当前Hit也包括“离开承诺路线、到出口未收到通过事件”等情况，不全是真碰撞。先为结算补充原因，区分真实碰撞、未完成原路线和证据缺失，再选择反馈文案。竞争计分沿用现行规则，不能因为换了文案就悄悄改变胜负。
3. 比赛胜负、当局观察、正式身份继承分别解释。可以复盘失败局中的可靠事实；只有符合现有晋升规则才写入下一代身份，不能让一句结算文案暗示已经发生继承。

## 4. 实施顺序与代码范围

| 顺序 | 改动 | 主要位置 | 检查重点 |
| --- | --- | --- | --- |
| 1 | 收紧反馈事实：路线选择与动作成败分开，补失败原因 | AIShadowRunner、PredictionGate、SingleContractFlow、EchoRunPresentation | 选了反制但未完成，不再显示预测命中；重复事件不重复结算。 |
| 2 | 精简常驻区，调整首页和结算的信息分配 | UIManager、EchoHudView、EchoHudPrefabBuilder及HUD预制体 | 领先、进度、伤势清晰；赛道视野不被文字遮挡。 |
| 3 | 临时提示淡入淡出、同事件合并和覆盖规则 | EchoHudPresenter、EchoHudView | 刷新不续期；同屏一条；暂停、重新开始后不残留。 |
| 4 | 用固定探测场景验证，不增加新AI模块 | 现有验证配置与门测试 | 临界线前后换道、改向、碰撞、未完成和重复事件都有可解释结果。 |

HUD预制体通过现有编辑器构建入口或序列化方式调整，保留资产标识。已有开场动作重演、身份存档和门事件系统继续复用。

## 5. 怎么验收

### 代码与运行检查

- 对新增结果原因、反馈映射和结算去重运行针对性测试。测试要覆盖不同事件确实得到不同结果，不能仅断言新文案存在。
- 用固定场景记录：锁线前临时改向、锁线后换路、选反制但撞击、成功通过、同一门触发改猜、证据不足。
- 实机检查：高速、屏幕尺寸变化、暂停/恢复、死亡/重开、减少动态效果。查看文字与底板一起淡出，关键路线信号持续到选择结束。
- 自动化测试只能证明规则与生命周期；是否看得清、是否妨碍竞速，需要实际画面和试玩确认。

### 第一轮陌生玩家检查

先做一次两三人的排错，再找六名未接触项目的人使用同一套场景。先让玩家自由描述，之后询问，避免把目标答案提示给他们。

1. 跑动中是否知道领先/落后，以及伤势状态？
2. 遇到关键选择时，是否因为读文字错过操作？
3. 看完结算后，能否分清“选了什么”和“有没有完成”？

第一版暂定通过线：六人中至少四人能正确说明比赛状态和关键选择结果；不能出现系统把实际操作失误写成“预测命中”的已确认案例。读字导致的漏操作须结合录像定位，出现重复问题就继续删减赛中文字。

这条通过线只验证信息和反馈改进，不等同于会话提出的“六人中四人自然识别第二局换了验证方法”。后者留给两局切片。

## 6. 下一版再验证的内容

- 两局约90秒、每局一到两个显性探测点：通过独立时长与节点配置实现。当前55秒校准、95秒挑战及5/6门校验需要一起处理，不能只删时间数组。
- 一个可跳过的赛前立约，以及遵守、背离、证据不足三个第二局分支。
- 真正更换探测方式。目前连续两次成功反制主要触发后续门改猜，不能把它当成已经实现了不同诱因验证。
- 高价值偏好：先补每次可选路线、收益、障碍干扰及跨局记录，再判断信号是否稳定。现有车道偏好数据不足以直接证明这一点。
- 回声提前提交路线并暴露超越机会。目前预测已通过领先距离结算影响比赛；新的路线因果需要单独做可玩验证。

这些项目应在第一版反馈清楚后，选择一个继续推进，不同时展开。
